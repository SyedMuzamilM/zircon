# Zed Git latency and sticky file headers

Date: 2026-11-11. All Zed evidence below comes from primary source at pinned commit `b5cd310b3b54dfc659fcc06453e6358843dfe216`, fetched from GitHub. This is a source audit, with no measured latency claim. Zircon observations refer to the current working tree and the supplied problem statement.

## Context expansion changes the projection

Zed's gutter expansion button calls `Editor::expand_excerpt`. The editor gets the configured expansion line count, preserves or adjusts scroll position where appropriate, then calls `MultiBuffer::expand_excerpts`. It does not reopen the source file or request a Git refresh. See [gutter button](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/element.rs#L2766-L2844) and [editor expansion](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/navigation.rs#L1581-L1638).

`MultiBuffer::expand_excerpts` resolves selected excerpt anchors, groups them by path, reads the existing source buffer snapshot, extends `context` row boundaries, and keeps `primary` ranges intact. It merges overlapping ranges and updates excerpts for those paths. The update reuses unchanged excerpts, shares the unaffected SumTree prefix/suffix, produces projection edits, synchronizes existing diff transforms, and publishes changes. It does not call the text diff algorithm. See [expansion](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/multi_buffer/src/path_key.rs#L226-L320), [excerpt reuse](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/multi_buffer/src/path_key.rs#L368-L503), and [projection publication](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/multi_buffer/src/path_key.rs#L602-L666).

This path is synchronous and still performs work proportional to the affected path's excerpts and projection changes. Calling it cheap means that it avoids file I/O and text comparison, not that it is constant-time. Split diffs also map the expanded right-hand excerpts into base-text ranges using the retained `BufferDiff`, then update the left-hand projection. See [split expansion and synchronization](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/split.rs#L1248-L1390).

Two Zed operations must stay distinct: excerpt expansion reveals surrounding source text; `expand_diff_hunks` reveals deleted diff content by changing diff transforms. The latter also uses existing hunk data. `set_all_diff_hunks_expanded` does not mean that every file's context is visible. See [diff hunk expansion](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/multi_buffer/src/multi_buffer.rs#L2326-L2508).

## Edits schedule buffer diffs separately from repository refresh

`Project::on_buffer_event` requests diff recalculation for an edited or reloaded source buffer. A set deduplicates pending buffers. With a nonzero `git.gutter_debounce`, Zed uses `DebouncedDelay` with a minimum of 50 ms; with zero it defers recalculation to the event loop. The async worker drains the set and processes buffers that arrive while it runs. These are per-buffer diff requests, not an unconditional repository status/patch reload after every keystroke. See [event and scheduling path](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/project/src/project.rs#L4114-L4245).

`BufferGitState` retains HEAD/index text and live diff handles. Recalculation stores a replaceable task, calls `BufferDiff::update_diff`, yields between phases, and can reuse the unstaged result for the uncommitted diff when index matches HEAD. `update_diff` uses a background executor and reuses hunks when source/base versions and base existence match. Otherwise `compute_hunks` materializes current text and computes a Histogram line diff, with hunk/word-diff processing. This is the expensive comparison path that excerpt expansion avoids. See [recalculation](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/project/src/git_store.rs#L5545-L5778), [background work and version reuse](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/buffer_diff/src/buffer_diff.rs#L1978-L2035), and [hunk computation](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/buffer_diff/src/buffer_diff.rs#L1224-L1287).

Installing a result emits `DiffChanged` with changed ranges. `DiffMultibuffer` subscribes per file and updates that file's excerpts. It deliberately skips range replacement while the display buffer is dirty, preserving the editable view; save triggers a refresh. `update_excerpts_for_path` preserves overlapping expanded context rather than resetting it to the default. See [subscriptions/range updates](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/git_ui/src/diff_multibuffer.rs#L438-L624), [save refresh](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/git_ui/src/diff_multibuffer.rs#L424-L427), and [context preservation](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/multi_buffer/src/path_key.rs#L102-L175).

Repository status/HEAD/branch events drive a separate `DiffBufferList` file-list path. Project diff refresh loads files in sorted order with at most 16 concurrent loads and explicitly yields between registrations, even when loads are already ready. Search likewise prepares excerpt ranges in background work and yields while installing streamed results. See [file-list events](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/project/src/git_store/diff_buffer_list.rs#L61-L113), [incremental diff loading](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/git_ui/src/diff_multibuffer.rs#L626-L765), and [search stream](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/search/src/project_search.rs#L653-L770).

## Source buffers do not require source tabs

`DiffBufferList::load_buffer` opens a buffer through `GitStore.buffer_store.open_buffer`, then obtains its uncommitted, unstaged, staged, or revision diff. It returns retained buffer/diff entities without calling a workspace tab-opening API. `BufferStore::open_buffer` returns an existing buffer by path or shares an in-flight load. Project diff adds the enclosing `ProjectDiff` item to the pane. See [diff buffer loading](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/project/src/git_store/diff_buffer_list.rs#L420-L510), [buffer deduplication](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/project/src/buffer_store.rs#L921-L974), and [project diff item](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/git_ui/src/project_diff.rs#L145-L167).

Workspace `open_path` is a different operation that loads an item and calls `pane.open_item`. Global search creates a `MultiBuffer` and a results editor over it, then adds the search view as a workspace item. Retaining buffers for an editable composite view therefore does not require hidden source tabs. See [workspace opening](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/workspace/src/workspace.rs#L5154-L5224), [search model](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/search/src/project_search.rs#L396-L425), and [search results editor](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/search/src/project_search.rs#L1613-L1618).

## Sticky file headers belong to viewport layout

The common editor supports both Git and global-search file headers. `BlockSnapshot::sticky_header_excerpt` seeks to the top display row in its transform tree and walks backward to the owning excerpt/file boundary. `EditorElement` uses that result during prepaint, renders visible blocks, and creates one floating file header. The normal header suppresses duplicate content while reserving its height. The floating header moves upward when the next file header approaches. See [owner lookup](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/display_map/block_map.rs#L2321-L2344), [prepaint integration](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/element.rs#L9259-L9365), [duplicate suppression](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/element.rs#L3449-L3478), and [floating/push-off layout](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/element/header.rs#L137-L227).

Split diff supplies a shared header layer across both columns with the same owner lookup and next-header push-off rule. These file headers are separate from syntax-based sticky scroll, which runs for singleton editors and requires the sticky-scroll setting. See [split header layer](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/split_editor_view.rs#L417-L462), [split push-off](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/split_editor_view.rs#L529-L613), and [singleton sticky-scroll gate](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/element.rs#L9406-L9424).

Viewport text shaping is another separate cost. Prepaint intersects editor bounds with the parent's content mask, derives `start_row..end_row`, and lays out lines in that range. This evidence supports visible-row shaping, not a claim that every display-map update is viewport-only or that expanding thousands of excerpts is free. See [visible bounds](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/element.rs#L8697-L8710), [visible rows](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/element.rs#L8756-L8778), and [line layout](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/editor/src/element.rs#L9160-L9170).

## Recommendations for Zircon

1. Replace the expansion chain in `views/git/diff_controls.zig` that synchronously calls `context.apply`, `Projection.init`, `rebuildEditable`, and `git_selection.rebuild` with an affected-file excerpt update over retained source/revision snapshots. Keep canonical diff hunks separate from revealed context. Reuse existing diff results and unrelated file projections, and preserve selection/scroll anchors across merges. Moving the same full rebuild to another callback would leave its cost intact.
2. Add document lookup/loading that retains workspace documents without `Shell.openPath`. Use document identity for Git/Search ownership; reserve tab creation for explicit file navigation. Remove `primary = false` tab creation from `rebuildEditable`. Dirty document lifetime and save/close behavior still need explicit ownership after tab separation.
3. Apply source edits immediately and queue affected document IDs for diff recomputation. Coalesce bursts, compute from immutable source/base snapshots off the UI thread, and validate source revision, comparison base, and view generation before publishing. Zed's 50 ms floor is evidence of its policy, not a measured optimum for Zircon. Keep full repository refresh for status/base changes, save, staging, and external changes rather than calling `services_git.start(.refresh)` after every Git edit.
4. Preserve expanded context and dirty editable excerpts while new hunks arrive. Publish updates per affected file and batch/yield initial large loads. Do not reset selection or rebuild every source editor for each result.
5. Give Git and Search the same sticky-file-header behavior using projected file ranges. Find the file at the top display row, paint its header at the viewport top, and use `min(viewport_top, next_header_y - header_height)` for push-off. Reserve normal header height, suppress duplicate painting, and use one header across split columns. Header lookup and scrolling should not trigger Git work or source loading.
6. Profile expansion/projection, source acquisition, text diff, selection remapping, and visible-row shaping separately. Acceptance should cover expansion between nearby hunks, repeated upward expansion without scroll jumps, typing during a pending diff, no hidden tab growth, and sticky push-off in Git and Search. This audit establishes architectural separation, not Zed/Zircon timing parity.
