📁 Package Structure & File Hygiene Audit (What Shouldn't Be There)

Inspection of packages/, apps/, build.zig.zon, and recent commits identified critical file placement issues and packaging anti-patterns:

⚠️
1. Raw Lucide SVG Assets in UI Source Tree:
packages/zircon_ui/src/controls/lucide/ contains 35 raw SVG files, LICENSE, and SOURCE.md. In packages/zircon_ui/build.zig.zon, .paths = .{ "src", ... } packages these into the package hash. The runtime only uses the compiled icon_paths.zig. The SVGs belong in tools/assets/lucide/ or root assets/, not in package src/.
⚠️
2. Bundled TTF Font Binaries Inside Package Source:
packages/zircon_ui/src/text/fonts/ contains IBMPlexSans-Regular.ttf (196 KB) and Lilex-Regular.ttf (190 KB), embedded via @embedFile. Placing raw font binaries in the core framework src/ directly inflates package tarballs and forces package hash churn. Should be in an assets directory or separate resource package.
⚠️
3. Compiled Mach-O Binaries in Repository:
artifacts/font-pass/baseline-zircon (1.4 MB) and baseline-text-bench (407 KB) are compiled 64-bit arm64 Mach-O executables committed or stored locally.
ℹ️
4. Cache Bloat (5.6 GB + 710 MB):
Root .zig-cache/ is 5.6 GB, and each package has its own local packages/*/.zig-cache/ totaling ~710 MB. Needs a zig build clean step and centralized cache policy.

⚡ Deep Architectural & Performance Comparison

Domain Zed (Rust / GPUI) Zircon (Zig / zigpui) Winner & Trade-offs
UI Architecture Hybrid retained/immediate; 3-phase Element (request_layout → prepaint → paint); Entity::cached subtree caching. Explicit double-buffered transactional frame arenas; staging → layout → hit-test → non-fallible swap; generational entity slab with borrow preflight. Tie. Zircon has cleaner transactional boundaries and runtime borrow preflight; Zed has subtree memoization.
Text Engine text::Buffer (CRDT ropes, fragment trees) → language::Buffer → MultiBuffer → DisplayMap (inlays, folds, wrap). Immutable AVL UTF-8 rope (rope.zig, 4 KiB leaves, checksummed summaries) → Document → Snapshot → Editor. Zed. Zed handles soft-wrap, bidi, grapheme clusters, multi-buffer excerpt editing. Zircon is code-point based.
Rendering & Shaders Platform-specific: Metal (macOS), WGPU/Vulkan (Linux), DirectX 11 (Windows). Single full-screen MSAA texture for arbitrary paths; SDF quads/shadows. Metal only (macOS). Direct ObjC runtime calls. 80-byte instanced vertex batches, 2048² R8 shelf glyph atlas with 4×4 subpixel phases. Zed (breadth/cross-platform) / Zircon (minimal zero-dep C-free Zig bridge).
Memory Model Unbounded cache growth. Known community issues with multi-GB RSS on large monorepos (e.g. #24724, #7939 ballooning to 4–20 GB). Strictly bounded caches: 4 MiB glyph atlas, 4 MiB shaping cache, 64 MiB image cache, 8 MiB retired frame arenas. ~10–30 MB idle floor. Zircon (by design). Far superior memory discipline and bounded guarantees, though unbenchmarked at enterprise scale.
Platform Support macOS (120 FPS ProMotion), Linux (Wayland & X11 via WGPU/Vulkan), Windows 10/11 (DirectX 11). macOS only. Linux only cross-compiles non-GUI portable tests (build.zig panics on native non-macOS). Windows has 0 support. Zed. Production cross-platform maturity.
Syntax & LSP Tree-sitter incremental parsing, ~80 LSP language servers, semantic tokens, hover, definition, rename, formatting, snippets. Lexical tokenization with fallback convergence; stdio LSP client supporting versioned diagnostics and completions only. Zed. Far broader language intelligence capabilities.
