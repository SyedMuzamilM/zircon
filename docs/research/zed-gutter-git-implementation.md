# Zed gutter and Git implementation reference

Inspected 2026-11-06 using the read-only sparse checkout at `/tmp/zircon-research/zed`, including `git show HEAD:path` for absent files. All upstream links pin commit [`4a6121bb0f10c6e8037b741b7dc0a4cd639ae289`](https://github.com/zed-industries/zed/tree/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289), committed 2026-11-05. These are source observations and implementation recommendations; Zed was not launched. No app code or assets were changed.

## Continuous gutter markers and inline hunk expansion

| Verified source behavior | Lesson for Zircon |
| --- | --- |
| [`layout_gutter_diff_hunks`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/editor/src/element.rs#L1866) enumerates hunks in visible display rows and installs a hitbox for each unfolded hunk when the tracked-file gutter is enabled. | Derive painting and hit testing from the same hunk geometry and current display snapshot. Keep diff markers separate from line-number selection targets. |
| [`paint_gutter_diff_hunks` and `diff_hunk_bounds`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/editor/src/element.rs#L5397) paint one rectangle across the display-row range. Added/modified/deleted use semantic theme colors. The default strip width is `floor(0.275 × line_height)`. Pure deletions with an empty current range get a widened rounded marker centered on the deletion boundary. Folded hunks get a modified marker, and ranges stop before excerpt headers. | Paint a continuous strip across adjoining changed rows, without gaps from per-row padding. Handle zero-row deletions explicitly. Map through wrapping, folding and scrolling before calculating bounds; clip to the editor viewport and file section. |
| [`mouse_left_down`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/editor/src/element/mouse.rs#L570) checks hunk hitboxes before normal gutter selection, calls `toggle_single_diff_hunk`, then returns. [`Editor::toggle_single_diff_hunk`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/editor/src/git.rs#L1825) delegates to the buffer. | A marker click expands or collapses only that hunk. It must not also move the caret or select the source line. |
| [`MultiBuffer` expansion](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/multi_buffer/src/multi_buffer.rs#L2980) inserts a `DiffTransform::DeletedHunk` referring to the base-text byte range and tracks the corresponding current-text range. [`expand_diff_hunks`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/multi_buffer/src/multi_buffer.rs#L2326) and collapse share the same expansion machinery. | Removed lines belong in a display projection backed by the comparison text. Keep current lines backed by the live buffer. Expansion must not insert removed text into the document or dirty the file. |

Suggested model: retain repository/file identity, comparison base, buffer version, old/new hunk ranges and expansion state. Build display rows such as `source`, `removed`, and `file_header`, each with explicit source mapping. Key interactions by hunk identity and snapshot generation so edits or a repository switch cannot redirect a stale click. This is a proposed Zircon design, not a description of Zed's exact data structures.

## Blame hover is a separate interaction

Zed has two blame presentations:

- The blame gutter renders abbreviated SHA, optional avatar, author and relative time. Its row opens `CommitView` on click and supplies a hoverable `CommitTooltip`. See [`render_blame_entry`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/blame_ui.rs#L153).
- The inline blame label appears after the current line, with configurable padding and minimum column. [`layout_inline_blame`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/editor/src/element.rs#L2132) calculates its bounds; [`mouse_moved`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/editor/src/element/mouse.rs#L85) keeps the popover open while the pointer is over either the label or popover. [`show_blame_popover`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/editor/src/git.rs#L1988) uses the configured hover delay and stores parsed commit-message/Markdown state.

Both detail presentations use a vertical card. The inline [`render_blame_entry_popover`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/blame_ui.rs#L302) has an author/avatar/email header, scrollable commit message, and absolute timestamp/SHA/actions footer. The gutter [`CommitTooltip`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/commit_tooltip.rs#L288) follows the same structure. Hovering commit metadata does not expand removed source lines; clicking the diff strip does.

The requested vertical centering is a Zircon acceptance requirement. Zed's inline [`layout_blame_popover`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/editor/src/element.rs#L2222) places the card above the target point when it fits, otherwise below, then adjusts horizontal overflow. It does not vertically center that card against the hovered line. For Zircon, center author/time text in its line-height box using font metrics. If the card itself must be centered alongside the line, measure it first, place its center at the line center, then clamp to the viewport and flip sides as needed. Keep that placement policy separate from the card's vertical content layout.

## Git controls, branches and stash

Zed's [`render_remote_button`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/git_ui.rs#L947) chooses Fetch when synchronized, Push when ahead only, Pull when behind, and Publish/Republish when upstream is absent/gone. Its [split-button menu](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/git_ui.rs#L1208) retains Fetch, Fetch From, Pull, Pull Rebase, Push, Push To and Force Push. Zircon can expose the requested fetch/pull/push controls directly while retaining this explicit operation state and remote selection.

[`GitPanel::fetch/pull/push`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/git_panel.rs#L4950) track a pending remote operation, handle credential prompts, clear pending state on task drop and show command output/errors. Push sets upstream when absent or gone. Use one repository service for these operations, update controls while busy, and refresh status, comparison text, branch and ahead/behind state after completion.

| Operation | Source-backed semantics |
| --- | --- |
| Fetch / pull / push | The [Git backend](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git/src/repository.rs#L2844) runs `git fetch` with a selected remote or fetch option, `git pull [--rebase] <remote> [branch]`, and `git push [--set-upstream or --force-with-lease] <remote> <local>:<remote-branch>`. Force push uses a lease. Pass arguments directly rather than constructing shell command strings. |
| Switch / create branch | [`change_branch`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git/src/repository.rs#L2386) distinguishes local and remote refs; remote selection establishes tracking before checkout. Creation runs `git switch -c <name> [base]`. The [picker confirm handler](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/branch_picker.rs#L1587) switches an existing branch, or creates a new branch from HEAD; secondary confirmation can use the default branch as base. |
| Stash scopes | The [panel](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/git_panel.rs#L3943) supports All, Tracked and Staged, with an optional message. The [repository store](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/project/src/git_store.rs#L8175) derives explicit paths. Tracked excludes newly created files, even staged additions, and returns early for an empty selection so it cannot accidentally stash everything. |
| Stash commands | The [backend](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git/src/repository.rs#L2641) uses `stash push --quiet --include-untracked [--message <text>] -- <paths>` for path selections, and `stash push --quiet --staged` for staged hunks. A path selection alone cannot preserve the scope of a partially staged file. Staged stash requires Git 2.35+. Apply/pop/drop accept an explicit `stash@{index}`. |
| Inspect / apply / pop stash | The [stash picker](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/stash_picker.rs#L300) opens a stash diff through `CommitView`. Normal confirm applies and retains the stash; secondary confirm pops. Drop and Show are distinct actions. Do not label a button merely "Restore" when its retention behavior is ambiguous. |

The [branch picker search](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/branch_picker.rs#L1450) filters All/Local/Remote, uses asynchronous fuzzy matching with smart case, and appends an explicit Create Branch entry when the query is not an existing name. New names are trimmed and spaces become hyphens. A select-only mode suppresses creation. The [stash picker search](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/stash_picker.rs#L393) fuzzy-matches formatted stash index/message, highlights match positions and clamps selection after filtering. Preserve object identity independently of filtered row position; refresh after any stash mutation.

## One combined diff for all files

[`ProjectDiff`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/project_diff.rs#L221) builds a `DiffBufferList` against HEAD and a `DiffMultibuffer`. The [Diff action](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/project_diff.rs#L124) can instead dispatch to branch diff according to `git.diff_base`. Label the comparison base explicitly; "all files" does not imply "against main".

[`DiffMultibuffer::new`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/diff_multibuffer.rs#L67) expands all hunks and creates one splittable editor. It [updates excerpts per path](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/diff_multibuffer.rs#L537) around changed ranges with context. [Reloading](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/diff_multibuffer.rs#L637) removes obsolete paths and loads files in order so later arrivals do not shift earlier sections unpredictably. Clicking a file can [navigate to its existing path location](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/git_ui/src/diff_multibuffer.rs#L261).

For Zircon, provide one scrollable document with file headers and ordered hunks, using the same old/new line model as inline expansion. Decide and label HEAD-to-working-tree, staged, and unstaged comparisons separately. A first version can use a unified read-only projection; editable excerpts and split diff are additional work. Binary files should have an explicit non-text state.

## Searchable settings pickers

Do not infer that every Zed settings dropdown is searchable. [`EnumVariantDropdown`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/settings_ui/src/components/dropdown.rs#L111) builds a checked context menu from a fixed variant list, without a query field.

The dedicated [`FontPicker`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/settings_ui/src/components/font_picker.rs#L80), [`ThemePicker`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/settings_ui/src/components/theme_picker.rs#L78), and [`IconThemePicker`](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/settings_ui/src/components/icon_theme_picker.rs#L92) use `Picker::uniform_list` and case-insensitive substring filtering. Empty queries restore the full list and select the current value. Filtered queries retain the current value if present, otherwise select the first result. Confirm invokes the setting callback only when a result exists; dismissal clears the query. Their matching is simpler than branch/stash fuzzy matching.

Global [settings search](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/settings_ui/src/settings_ui.rs#L2309) is another separate mechanism. It merges all-query-word prefix matches with fuzzy results scoring at least 0.5, supports `#` JSON-path queries, and cancels the previous search task. Its [index](https://github.com/zed-industries/zed/blob/4a6121bb0f10c6e8037b741b7dc0a4cd639ae289/crates/settings_ui/src/settings_ui.rs#L2399) includes page/section names, item titles and descriptions.

For the requested UI, use a reusable searchable choice popover for long option sets, with search focused on opening, keyboard selection, current-value indication, an empty-results state, Enter to commit and Escape to dismiss. Keep the selected value separate from the query and highlight. Persist through the existing settings service; search itself must not change a setting. These keyboard and persistence requirements are proposed acceptance behavior, not claims verified in the picker delegates alone.

## Delivered in Zircon

The implementation now shares marker geometry between drawing and hit testing, reserves display rows only for removed hunk text, and keeps blame in a separate hover card. It adds keyboard hunk navigation, theme-aware colors, centered metadata and scrolling commit messages. Git actions use owned jobs; clean file buffers reload after worktree mutations and dirty buffers block those mutations. A combined HEAD-to-worktree review retains staged changes and includes untracked files.

Branch, stash and remote pickers use case-insensitive substring search with keyboard selection and scrolling. Settings choices have their own search field, selection indication and Enter/Escape behavior. SVG sources now live in `assets/icons`, including the pinned artwork and ISC notices. Repository tests exercise local bare-remote sync, branch creation/tracking, stash inclusion and conflict retention. The original acceptance list below also names broader future scope such as wrapping/folding and destructive operations; it is not a claim of complete Zed parity.

## Feasible acceptance criteria

These are proposed checks for the implementation, not completed validation.

1. In a real temporary repository, add a multiline block, modify adjacent lines and delete a block. Added/modified ranges paint uninterrupted semantic-color strips; pure deletions remain clickable at start, middle and EOF. Scrolling, wrapping, folding and resizing keep markers aligned and clipped.
2. Clicking a marker reveals that hunk's removed base lines and highlighted current additions inline. A second click collapses it. Neither action changes file bytes, dirty state, caret or undo history. Added-only hunks have no invented removed text. Adjacent hunks and file headers remain distinct.
3. Hovering author/time shows the correct author, full message, absolute time and SHA. Metadata is vertically centered within its source line. The detail card remains reachable by pointer, stays within the window and does not cover unrelated controls. If centered beside the line, its center matches the line center unless viewport clamping is required. Hover details and hunk expansion can coexist.
4. Use two disposable clones and a local bare remote to verify fetch, pull, push and initial upstream publication. Controls show pending/error/success state, reject duplicate dispatch while busy, and refresh branch counts and diff afterward. Missing remotes and detached HEAD produce truthful available actions.
5. Branch search selects an existing local branch, tracks a remote branch and creates a named branch. Dirty-worktree checkout failure is surfaced without losing edits. Switching repositories while a picker or task is open cannot act on the wrong repository.
6. Stash All includes untracked files; Tracked leaves newly created files alone; Staged preserves unstaged hunks in a partially staged file. Empty tracked selection is a no-op. Apply retains a stash, successful Pop removes it, and Show displays its actual diff. Failed/conflicting Pop must not be reported as successful removal.
7. "All changes" opens one ordered scrollable diff with file headers for at least three changed files, including a deletion and an untracked text file. Clicking a file navigates within it. The displayed base/scope is explicit, and refresh removes reverted files without duplicating sections. Binary changes show a non-text state.
8. Long settings choices support focused search, case-insensitive filtering, arrows, Enter, Escape, current-value indication and zero results. Querying or dismissing leaves the setting unchanged; committing persists it across reopening. All settings search and option-list search remain independent.
9. Icons render from shared SVG assets, tint correctly in light/dark themes, preserve fills/opacity, and align at 1×/2× scale. Any imported Zed icon ships with the full ISC notice and recorded source revision. No guessed filenames or per-button duplicate SVG geometry.
