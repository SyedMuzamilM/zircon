## Method and limits
- Method: independent visual inspection of all 35 PNGs + source/test reading noted above; verified claimed changes (disabled Commit, extension selection vs row/hover, clickable breadcrumbs, indent guides, overflow/pane containment, stronger light tokens, new native captures) in both pixels and `theme.zig/canvas.zig/chrome.zig/shell.zig/manifest.json`.
- Limitations: static screenshots do not prove keyboard behavior, Git semantics, responsiveness, IME, VoiceOver, or frame-rate. Native tests use hidden AppKit windows with window-bound events (`inspection.md:27`) and 57 native tests reported passed plus Linux cross-build/ReleaseFast/SVG check – treated as reported correctness, not re-run here (no test execution per constraints). No desktop driving/app launch; completion capture `zircon-dark-completion.png` is 1200×760, not matched 1240×820 geometry, so treated as behavioral evidence only. Tab/stack narrow clipping unverified visually.
- Full parity vs rubric quality: Zircon implements the rubric workflows above with usable quality (7/10), but lacks full Zed feature parity – arbitrary pane trees (binary splits only), native menu/terminal/debugger, collaboration, LSP navigation/refactoring, complete Vim, soft wrapping/grapheme, semantic (symbol) breadcrumbs and diff headers, Unicode-aware search, full settings surface. Scores must not be reported as full parity.
